关于

先把声音拆开，再谈音乐

一个用交互实验台讲乐理的静态站：每个概念都配一个能拖、能听、能看见结果的台子。

给读者

它解决什么问题。乐理书上的话大多是对的，但读起来像在背条文： "纯五度是 3:2"——然后呢？这个站的做法是把每一句话做成一个能动手的东西： 泛音列可以一个一个关掉听，五度的音分可以拖着看整圈会不会合上， 卡农的四个声部可以看着它们依次进来。

怎么用。从第 0 节顺着走最省力， 因为后面的每一节都假设你听过前面那些声音。找正文里的某个说法用搜索， 想查某个词就翻术语表， 想看某个作品怎么拆就跳到课程地图的第三部分。

四个部分。

第一部分 · 乐理基础
23 节（第 0–22 节）。从泛音列与十二平均律开始，一路到音程、节奏、音阶、和声。
第二部分 · 编曲与作曲
10 节（第 23–32 节）。动机、轮廓、律动、和弦进行、织体、配器、曲式，外加 MuseScore 三节。
第三部分 · 作品分析
按"层"组织，不编号：贝多芬、巴洛克、莫扎特、俄罗斯与东欧、晚期浪漫与二十世纪、动画与管乐、摇滚与交错织体。
第四部分 · 风格解析
一种风格能被认出来，靠的是几条固定手法——目前有 Afrobeat 与拉格。

关于声音。全站没有任何音频文件： 声音都是浏览器里当场合成的（加法合成 + Karplus-Strong 拨弦 + 噪声打点）。 所以站点很小、加载很快，代价是音色不像真乐器。 谱例图是用 MuseScore 命令行渲染的，也没有外部字体依赖。

许可与引用。这个站是开源的：代码 MIT，教学内容 CC BY-SA 4.0。 转载、改编、拿去上课都可以，署名并以相同方式共享即可。

给贡献者

这个项目按"正规维护"来跑：main 不直接提交，每个改动一条分支 + 一个 PR， 合并前必须过 CI（跑数据审计）。三条底线写在 仓库的 CONTRIBUTING.md 里：

一 · 数据可核对。页面里的速度、调性、拍号、时长、署名、日期， 要么有出处，要么变成审计里的一条断言。凭记忆写下来的数字不收。

二 · 页面要快。单图不超过 400KB，不引入外部依赖， 能不用二进制的就不用。

三 · 交互必须有反馈。点了要看得见它在响、在走、还是结束了。

想加一首曲子

作品分析是会长大的模块。第三、四部分不编号—— 插一首曲子只要在课程表里加一行，不用动别人。完整流程见 docs/新增一首曲子.md：

  1. 先写下这一节的中心论点（一句话，而且能用耳朵验算）；
  2. 核事实：两个独立来源对得上才写，没有出处就不写；
  3. 起分支 codex/<主题>，定它放在哪一层；
  4. 需要动手验算的地方就做实验台（素材标明"本站自己写的示意"）；
  5. 写页面（开场 / 资料卡 / 正文 / 实验台 / 听点 / 参考 / 一句话带走）；
  6. 把这次引用的新事实加进审计，跑绿，开 PR。

想修东西

去仓库开 issue，三类模板随你挑： 交互问题（按钮、滑块、播放）、内容错误（乐理说法、数字、出处）、 新曲目提案。内容错误最好带上"你认为正确的是什么"， 我们会把这条错误变成审计里的一条防线。

本地怎么跑

python3 scripts/serve.py 5200     # 本地预览，禁缓存
node scripts/audit-music.mjs      # 数据审计（乐理数字、页面、编号、实验台注册）
node scripts/check-links.mjs      # 外链体检（需代理的站加 --proxy）

维护历史记着每个版本加了什么，也是这个项目怎么长起来的流水账。
