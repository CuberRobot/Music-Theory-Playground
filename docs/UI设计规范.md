# Music Theory Playground UI 设计规范 · v1.0

> 具体数值写在 [`styles/tokens.css`](../styles/tokens.css)，这份文档解释"为什么是这些数值"。

## 1. 设计关键词

**纸张 · 温度 · 可触摸 · 安静 · 清晰**

整体气质应该像**一本会动的米色练习册**，而不是一个科技感数据面板。
判断标准很简单：如果某个界面截图放在一本乐理书旁边显得格格不入，就是跑偏了。

## 2. 色彩系统

### 2.1 基调三色（你指定的）

米白不是"白色带点灰"，而是**暖的纸色**。所有中性色都偏黄，没有任何一个颜色是冷灰。

| 角色 | 令牌 | 值 | 用在哪 |
| --- | --- | --- | --- |
| 米白（页面底） | `--bg` | `#F7F3E9` | 页面背景，占屏面积最大 |
| 纸面 | `--surface` | `#FFFDF7` | 卡片、实验台、谱面 |
| 黄 | `--amber` | `#EFC24C` | 主音/根音、当前焦点、主按钮、高亮 |
| 绿 | `--green` | `#4C9A6A` | 稳定、协和、正确、已完成 |
| 暖黑 | `--ink-1` | `#2E2A22` | 正文与标题。**不用纯黑**，纯黑压在米白上会有印刷感 |

### 2.2 功能色（建议引入，待你确认）

只有米白/黄/绿会撞语义：**"这个音是正确选项"和"这是大调"都想用黄绿**。
所以建议再引入两个**受限场景**的功能色，它们不参与主视觉，只在需要区分时出现：

| 令牌 | 值 | 场景 | 为什么是这个颜色 |
| --- | --- | --- | --- |
| `--clay` 陶土红 | `#D4714C` | 张力、不协和、答错 | 和米黄绿同属暖色系，不破坏整体统一，不会像正红那样刺眼 |
| `--slate` 灰蓝 | `#6C8797` | 中性对照、次要数据、背景音 | 唯一的中性冷色，用来表示"不参与比较的东西" |

如果坚持只有三色，退路是：用**黄的高饱和 / 低饱和**表示大小调，用**绿 + 虚线边框**表示正确。
能work，但可读性会下降一档。

### 2.3 音乐语义映射表（这是全站最重要的颜色约定）

颜色一旦和乐理概念绑定，就必须在每一章保持完全一致：

| 乐理语义 | 颜色 | 说明 |
| --- | --- | --- |
| 主音 / 根音 / 引力中心 | 黄 `--amber` | 全站的"家" |
| 当前正在发声 / 焦点 | 黄浅底 `--amber-soft` + 黄描边 | 不要用别的颜色表示"当前" |
| 稳定 / 协和 / 解决 | 绿 `--green` | |
| 紧张 / 不协和 / 悬而未决 | 陶土红 `--clay` | 只在需要和"稳定"同时出现时用 |
| 中性音级 / 未激活 | `--surface-2` + `--ink-3` | |
| 正确 | 绿；答错 | 陶土红 + 重播，不出现惩罚性动效 |

**反例（要避免）**：给七个音级各配一种彩虹色。
这会让"颜色"这个通道承载太多信息，反而看不懂。音级之间的差别应该用**位置、大小、明度阶**表达。

### 2.4 三条颜色铁律

1. **黄色是面，不是字。** `#EFC24C` 上放深色文字；如果需要黄色文字，用 `--amber-deep #B9861F`。
2. **同一屏最多两个语义色。** 出现第三个时，先问哪个可以退成中性。
3. **所有色值来自 tokens.css。** 页面里出现任何十六进制色值都算 bug。

## 3. 字体与排版

| 用途 | 字体 | 理由 |
| --- | --- | --- |
| 标题 | 思源宋体 / Songti SC（衬线） | 书卷气，和米白纸面呼应。**只用在标题**，正文用宋体在屏幕上很难读 |
| 正文 / UI | 思源黑体 / 苹方（无衬线） | |
| 乐谱记号 | Bravura（SMuFL，SIL OFL 开源） | 符头、升降号、休止符的唯一正确来源，后期本地化子集 |
| 数值（频率、音分） | 等宽 + `tabular-nums` | 数字变化时不跳动 |

排版规则：

- 中文正文行高 `1.75`（比英文松），最大行宽 `68ch`，超过就断行——不然眼睛会横跨整个屏幕。
- 只有两级字重：`400` 和 `500`。用字重堆强调会让页面变吵，强调优先用颜色和位置。
- 术语**第一次出现时加粗**，之后不再加粗。

## 4. 栅格与布局

桌面端是**三栏**：

```text
┌──────────────────────────────────────────────────────┐
│ 顶栏：章节名 · 进度 · 声音开关                          │
├──────────┬──────────────────────────┬────────────────┤
│ 学习地图  │ 主体内容 / 实验台          │ 参数面板        │
│ 240px    │ 自适应，最大 68ch 正文     │ 320px，可折叠   │
│ 可折叠    │                          │                │
└──────────┴──────────────────────────┴────────────────┘
```

- `< 1280px`：收起右侧参数面板，参数移到实验台下方横排
- `< 1024px`：收起左侧地图，改为顶部汉堡菜单
- `< 720px`：单列，实验台占满宽度，正文上下留白收紧

## 6. 具象化隐喻系统（核心）

这是整个项目最值钱的部分。**不能每章换一个随机的比喻**，那样风格会散。

全站用一个元隐喻统摄所有具象化：**引力与地形**。

> 音高是高度，主音是引力中心（谷底/家），
> 越不稳定的音悬得越高，音乐的进行就是"爬升 → 悬停 → 落回谷底"的过程。

在这个隐喻下，每个概念的具象化方式：

| 乐理概念 | 隐喻 | 视觉 | 用户能做什么 |
| --- | --- | --- | --- |
| 音高 / 频率 | 高度 | 竖向位置 | 上下拖动，实时出声 |
| 半音 / 全音 | 台阶间距 | 宽窄不同的台阶 | 走格子数台阶 |
| 八度 / 音组 | 循环 | 螺旋上升一圈回到同名音 | 沿螺旋连续拖 |
| 等音 | 一个位置、两个名字 | 同一点上标签双面翻转 | 点击翻转标签 |
| 音的长短 | 长度 | 横向色块 | 拖两端拉伸 |
| 拍 / 节拍 | 脉冲 | 周期性扩散的圆环 + 重音梯度 | 打拍子、换拍号 |
| 切分音 | 错位 | 网格里跨过强拍的块 | 拖动块偏移 |
| 音程 | 跨度 | 两根柱子 + 中间台阶数 | 拖柱顶，看到度数/音数同时变 |
| 协和 / 不协和 | 干涉 | 两条波形叠加，拍频越快抖动越明显 | 拖动听拍频 |
| 和弦 | 堆叠 | 柱子垒起来，顶端连成斜面 | 拖音块堆叠，自动命名 |
| 和弦转位 | 旋转 | 底部的柱子被搬到顶端 | 把柱子扔到顶上 |
| 音阶 | 环形阶梯 | 一圈格子亮起 7 个 | 换起点 |
| 调式 | 引力场 | 引力阱曲线，主音在谷底 | 换谷底位置听整条曲线变 |
| 音级功能 | 势能 | 每个音的悬挂高度，导音悬得最高 | 拖着音听它想往哪走 |
| 调性关系 | 地图 | 五度圈当罗盘，近关系调是邻居 | 拖动罗盘指针 |
| 转调 | 旅行 | 地图上两点之间的路径动画 | 选择目的地 |

**这套隐喻的三个好处**：组件可以复用（音程塔和和弦堆叠是同一套几何）、
用户跨章节的直觉可以累积（第 4 章学的"高度"在第 6 章还能用）、
视觉语言自然统一（同一套"高度/距离/引力"的图形语言）。

## 7. 动效与声音反馈

**调度**：声音和动画都由 `AudioContext.currentTime` 驱动，不用 `setTimeout` 和 `requestAnimationFrame` 各自跑。
这是"视觉与声音同帧"唯一可靠的实现方式。

**动效原则**

- 有物理感，不要弹跳炫技。缓动用 `--ease-out`，时长 120–360ms。
- 音高变化时位置**连续插值**，绝不跳变——跳变会切断"高度=音高"的直觉。
- 不做纯装饰动画。每个动画要么在传达状态，要么在传达因果。
- 尊重 `prefers-reduced-motion`（tokens 里已经把时长归零）。

**声音原则**

- 默认音量克制（峰值 ~0.25），不吓人。首次点击才初始化 `AudioContext`。
- 用简单波形（三角波/正弦）加自定义 ADSR 包络。不追求音色逼真，追求**音高关系准确**。
- 正确/错误的音效不用"叮咚"，用音乐本身：正确 = 解决到主音，错误 = 停在导音上悬着。
  这样音效也在教学。

## 8. 无障碍与响应式

- 每个声音事件都有视觉等价物；**静音状态下不丢任何信息**（见方案第 3 节）。
- 键盘可操作：Tab 顺序自然，滑块支持方向键，空格播放。
- 对比度：正文 `--ink-1` on `--bg` 约 12:1；辅助文字最低用 `--ink-2`，不要用 `--ink-4` 写正文。
- 移动端触控目标 ≥ 44×44px。实验台在窄屏改为纵向堆叠。
- 不依赖颜色单独传达信息：协和/不协和同时用颜色 + 波形形状 + 文字。

## 9. 三个视觉方向（需要你选一个）

同样是"米白 + 黄 + 绿"，密度和气质可以差很远：

| | A · 练习册 | B · 实验台 | C · 绘本 |
| --- | --- | --- | --- |
| 气质 | 安静、克制、书卷气 | 可玩、现代、有仪表感 | 亲和、活泼、隐喻最强 |
| 标题 | 衬线宋体，大 | 无衬线，中 | 衬线 + 手写感，特大 |
| 容器 | 细线框，几乎无阴影 | 卡片 + 圆角 + 阴影 | 手绘不规则描边 + 实色块 |
| 控件密度 | 低，大量留白 | 高，参数常驻 | 低，但元素更大 |
| 黄绿的用法 | 只做批注和标记 | 做仪表、状态灯 | 做整块填充 |
| 风险 | 可能显得"教科书"、无聊 | 容易滑向"数据面板"，丢掉纸感 | 章节多了会幼稚，且难做密内容 |

我的建议是**混合**：正文和术语区用 A（克制、好读），
实验台用 B（卡片化和阴影让"可操作"这件事一眼可见），
每章末尾的沙盒用 C（允许夸张，因为那是玩的地方）。
这样既统一又有层次，而不是三个方向里挑一个。

### 决策（2026-09-18）：以 B · 实验台为基调

已选定 B。由此确定的三件事：

- **卡片、圆角、阴影是主要容器语言**，细线框只在需要弱分隔处使用，不拿来当卡片边框。
- **黄绿承担"仪表"角色**：状态点、读数、进度、开关，而不只是文字批注。
  这也是引入陶土红/灰蓝的另一个理由——仪表需要能表示"好/一般/差"三档。
- **控件常驻**：实验台的参数面板默认展开，不做"点开才看见"，因为可操作性要一眼可见。

## 10. 深色模式（2026-09 起）

深色模式**不是第二套样式**，而是同一组设计令牌换一组值 —— 组件一行都不用改，
只需要在 `styles/tokens.css` 里再写一份变量。

### 三条规矩

1. **组件里不许写死颜色。** 所有颜色都从 `--*` 令牌取。
   唯一允许写死的是"压在强调色上的字"，见下面第 3 条。
2. **色相不变，只翻明度关系。** 黄仍然是焦点、绿仍然是稳定、陶土仍然是张力；
   深色底上这些颜色要**更亮**才读得清，所以 `--amber-deep` / `--green-deep` /
   `--clay-deep` 在深色下反而比原色浅（浅色模式里它们是用来当文字的深色版，
   深色模式里反过来）。
3. **落在强调色上的文字单独给令牌。** `--on-accent`（压琥珀黄，恒为深墨）
   与 `--on-green`（压绿，恒为浅色）。
   **不要用 `--ink-inv` 顶替** —— 它在浅色下是白的，白字压亮黄会糊。

### 触发方式

- 跟随系统：`@media (prefers-color-scheme: dark)`；
- 手动切换：`<html data-theme="dark|light">`，选择存在 `localStorage['mtp-theme']`，
  顶栏那颗按钮由 `main.js` 注入；
- **防闪白**：每个 HTML 的 `<head>` 里有一段 4 行内联脚本，在样式生效前就把
  `data-theme` 设好 —— 否则"系统浅色 + 用户选深色"时会先闪一下白。
  新增页面时**别忘了抄这 4 行**（`lessons/index.html` 曾经漏过，见 issue #10-1）。

### canvas 与"画上去就不管了"的图形

用 CSS 变量上色的地方，浏览器自己会跟着主题换。但 canvas 不行：颜色是在画的那一刻
复制进像素里的。这类图形必须监听 `mtp:theme-changed` 自己重画 ——
目前全站只有泛音实验台的波形需要这么做（`harmonic-lab.js`）。

---

仍然需要你拍板的一点：**标题要不要继续用衬线宋体**。
B 原本的方案里标题是无衬线，但衬线标题更能撑住"纸感"，和米白底色是一伙的。
我倾向于保留衬线做 `h1`/`h2`，正文和 UI 控件用无衬线——这样 B 的可玩性有了，
又不会滑向纯数据面板。`styles/tokens.css` 目前就是按这个写的。

C 的绘本气质不退场，集中用在每章末尾的沙盒区（那里允许夸张，因为就是给人玩坏的）。
