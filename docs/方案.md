# MusicL 项目方案 · v0.1 草案

> 这份文档回答"做什么、不做什么、怎么搭、按什么顺序做"。
> UI 细节见 [UI设计规范.md](UI设计规范.md)，内容来源见 [参考书与章节大纲.md](参考书与章节大纲.md)。

## 1. 一句话定位

一个用**看得见的声音**讲乐理的交互式静态站：每个概念都配一个能拖、能听、能立刻看到结果的实验台。

关键词是"具象化"。市面上讲乐理的网站大多是**文字 + 静态谱例 + 播放按钮**，读者靠想象把符号翻译成声音。
这个项目要做的是反过来：**先给一个可以乱玩的物理对象，再把术语贴在它身上。**

## 2. 目标与非目标

**要做的（v1 范围）**

- 中文乐理，从零基础讲到调性关系，覆盖面大致相当于李重光《音乐理论基础》
- 每个知识点 = 引子 + 具象化实验 + 术语与规则 + 听辨挑战 + 自由沙盒
- 纯前端静态站：零后端、零账号、零依赖，可离线（字体除外）

**明确不做的（至少 v1 不做）**

| 不做 | 原因 |
| --- | --- |
| 曲谱库 / 播放器 | 是另一个产品，会把项目拖垮 |
| 音频文件上传、AI 批改 | 需要后端 |
| 严格对位写作训练 | 进阶内容，等基础章节稳定后再说 |
| 用户系统、排行榜 | 静态站不做状态同步 |
| 完整五线谱编辑器 | 只在"需要看懂谱面"的地方自绘必要元素 |

## 3. 使用者与场景

**主要用户**：自学乐理的成年人，可能会一点乐器，也可能完全零基础。要的是"我大概明白了"而不是考试。

**两个典型场景**

| 场景 | 设备 | 要求 |
| --- | --- | --- |
| A 学习 | 桌面浏览器，一次 10–20 分钟 | 大实验台、可拖拽、可对比 |
| B 复习 / 听辨 | 手机竖屏，碎片时间 | 单手可操作、小挑战卡片 |

**一条容易被忽略的硬约束：默认静音也要能读。**
很多人在办公室或图书馆打开网页，声音是关着的。所以每个声音事件都必须有视觉等价物——
音高有高度，时值有长度，协和度有波形和颜色。声音是增强，不是载体。

## 4. 核心设计原则（具象化五原则）

1. **先听见，后命名。** 术语出现之前，先让人玩过这个现象。先让人听出"这个音在往家走"，
   再告诉他那个音叫"导音"。
2. **一个概念，一个控件。** 一屏里只有一个可以拖的东西。十个滑块等于没有交互。
3. **视觉与声音同帧。** 发声和动画共用同一个 `AudioContext.currentTime` 调度，
   不用 `setTimeout` 各自跑。目标是点击到发声 < 30ms。
4. **可逆、可乱玩。** 任何操作都能一键还原，不设惩罚。错误是信息，不是失败。
5. **一章一沙盒。** 每章末尾给一个不设对错的自由实验区，让人把刚学的概念用坏。

## 5. 技术选型

| 项 | 选择 | 理由 | 放弃的方案 |
| --- | --- | --- | --- |
| 构建 | **零构建**，原生 ES Modules | 依赖为零、离线可用、GitHub Pages 直接托管；本项目体量不需要打包器 | Vite：多一层 npm 依赖，收益小于复杂度 |
| 声音 | **Web Audio API 实时合成** | 无音频素材、毫秒级响应、参数可连续变化（频率、包络、泛音数），能直接支撑"实验台" | 预录 mp3 / soundfont：体积大，且无法做参数化实验（拖音高时不能连续变调） |
| 图形 | **SVG 为主 + Canvas 为辅** | SVG 可交互、可无障碍、可 CSS 动画，适合谱面与几何；波形/频谱用 Canvas | 纯 Canvas：可访问性差；第三方乐谱库：依赖重 |
| 乐谱 | **自绘 SVG** | 需求有限（音符、谱号、时值、升降号） | VexFlow / abcjs：后期需要再本地化引入 |
| 样式 | **原生 CSS + 设计令牌** | 与零构建一致；`styles/tokens.css` 是唯一真源 | Tailwind：需要构建 |
| 字体 | 系统字体栈起步，后期本地化 | 离线优先 | 在线字体 CDN：断网即失效 |
| 部署 | GitHub Pages | 免费、静态、够用 | — |

**有一个技术债要提前说清**：乐谱记号需要 SMuFL 字体（Bravura 是 SIL OFL 开源的），
否则符头、升降号、休止符只能用丑的 Unicode 拼。计划是先自绘 SVG 图形绕开一段时间，
等谱面需求变复杂时再把 Bravura 子集本地化进仓库。

## 6. 信息架构

```text
MusicL/
├── index.html              # 首页 = 学习地图，不是 landing page
├── lessons/
│   ├── 01-pitch/           # 一章一目录，结构完全一致
│   └── ...
├── labs/                   # 独立实验台，可被多章复用，也能单独分享链接
│   ├── harmonic-series/
│   ├── interval-tower/
│   ├── circle-of-fifths/
│   └── gravity-field/
├── styles/
│   ├── tokens.css          # 设计令牌：色彩/字体/间距/圆角/动效
│   ├── base.css            # 重置与基础排版
│   └── components.css      # 通用组件
├── src/js/
│   ├── audio/              # 合成引擎：音源、包络、混响、调度器
│   ├── music/              # 纯数据模型：音高、音程、和弦、音阶、调
│   └── widgets/            # 交互组件：键盘、音程塔、和弦堆叠、节拍格…
├── docs/
└── scripts/dev.sh
```

**为什么首页是学习地图而不是落地页**：这个站的回头客远多于新访客，
第一屏应该直接是"我学到哪了、下一节是什么"。

**为什么 `labs/` 要和 `lessons/` 分开**：一个实验台（比如五度圈）会被讲调号、
讲关系大小调、讲转调三章复用。实验台是资产，章节是编排。

## 7. 章节页模板

每一章都按同样的六段式走，保证界面风格统一：

1. **引子**：一句问题 + 一个能立刻玩的东西（不解释，先玩）
2. **具象化实验**：主实验台，可拖可听，配一句"你现在看到的是……"
3. **术语与规则**：这时候才出现名词、定义、谱例。左侧正文 + 右侧实时呼应的小图
4. **听辨挑战**：3–5 题，答错只是重播，不扣分
5. **自由沙盒**：关掉提示的实验台
6. **小结**：3 条要点 + 下一章钩子

## 8. 里程碑

| 阶段 | 产出 | 状态 |
| --- | --- | --- |
| **M0** | 目录初始化、设计规范、章节大纲 | ← 当前 |
| **M1** | 设计系统落地 + 首页学习地图 + 1 个样板章节（音程）走通全部六段式 | |
| **M2** | 第 0–3 章：泛音、音高、时值、节奏 | |
| **M3** | 第 4–5 章：音程、和弦 | |
| **M4** | 第 6–8 章：调式、调内和声、调性关系 | |
| **M5** | 附录：术语表、五度圈、和弦速查；移动端打磨 | |

M1 是最关键的一步——样板章节确定了，后面就只是复制节奏。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 声音在不同设备上音色差异很大 | 用简单波形 + 自定义包络，不追求音色逼真；重点是音高关系准确 |
| 可视化越做越花，风格散掉 | tokens.css 是唯一颜色来源；新组件先写进规范再写代码 |
| 章节页越来越多，重复代码膨胀 | `labs/` 与 `src/js/widgets/` 强制复用；重复三次以上必须抽组件 |
| 内容准确性出错（尤其调号、音程性质） | `src/js/music/` 写成纯函数并配断言测试；关键数据用真钢琴/调音器复核 |
| 中文字体在离线时回退难看 | 只用系统字体栈，不依赖网络字体；字体差异不承载信息 |

## 10. 需要你拍板的开放问题

1. **功能色**：只用米白/黄/绿会撞语义——"正确"和"大调"都想用黄绿。
   我建议引入陶土红（张力/错误）和灰蓝（中性对比）作为受限功能色，见 UI 规范第 2.3 节。
2. **章节顺序**：走参考书的线性顺序（音高→时值→节奏→音程），
   还是玩法驱动（先音程和和弦，因为好玩，时值/节奏往后放）？我倾向前者，但第 0 章泛音可以放到最前。
3. **双语术语**：正文只写中文术语，还是中文（English）并列？并列对查资料友好，但正文会变吵。
4. **移动端优先级**：做成"能用"还是"优先"？后者会显著影响实验台的布局方案。
5. **进度保存**：不做账号的话，用 localStorage 记"看过的章节"要不要？
6. **项目名**：MusicL 的读法确认一下（Music + L？MusicLab 的缩写？），首页标题要定稿。
